# AI 时代产品工程：从业务问题到可验证智能系统

AI 产品不是在旧软件里加一个聊天框。真正的变化是：人先把问题、材料和决定说清楚，再让模型调用合适的能力，最后用检查结果决定继续、修改还是停下。

全课沿一条主线展开：

```text
Prompt：先让一次回答有用
→ Agent + Skills：再让系统会选择工具、完成作品
→ Loop：最后让多步任务能够检查、修正和停止
→ 综合业务案例：把能力装进真实角色、数据和流程
```

数据分析贯穿三段主线：先提出可以计算的问题，再让 Agent 调用分析 Skill，最后把体检、计算、写作和复核连起来。

## 逻辑思维主线

本课程贯穿一条逻辑思维主线：演绎（必然）与归纳（或然）的张力。具体表现为：

- 命题化是起点：把模糊表述变成可验证的陈述句（观察/命题/前提/推断/动作五层拆分）
- 事实与观点分离：推理建立在可验证的事实上，观点不作为前提
- 演绎执行规则，归纳提出候选：两者接力，归纳不越过权限门禁
- 相关性是线索不是结论：共变≠因果，确定因果需实验控制混杂
- 证伪是验收口径：找反例检验结论是否说得太满，而非追求"一定对"
- 逻辑有边界：证据不足/高影响/不可判定时悬置判断，交由人工

这条主线在 01 章集中讲解，在 02—07 章的 Prompt/Agent/Skill/Harness/Loop 中实践，在 13—21 专题的架构与工程规范中落地为门禁和适应度函数，在 B13—B20 案例中作为工业场景的方法论骨架。
