# 高峰时段，履约域要不要拆？

本案例把两类材料并排使用，不能混写成同一种事实：

- `case.csv`：12,000 行公开 O2O 拣货基准的固定派生切片，来源 ID 为 `DATA-07`。
- `operational-evidence.csv`：56 行确定性合成的中国前置仓运营证据，来源 ID 为 `COURSE-OPS-07`。

运营证据的请求量以公开切片的 4,000 单/日为缩放锚点，延迟场景以公开切片的商品数 p90=9 为固定输入；发布、故障和恢复值仍是课程内确定性场景，不是从公开来源观测到的生产指标。

运行 `python transform.py` 可重新生成运营证据；若需要从仓库内固定的原始压缩包同时重建公开切片，运行 `python transform.py --rebuild-public`。

## 使用边界

- 公开基准只证明订单到达与商品集合，不包含库存、拣货、配送或真实业务结果。
- 中国运营证据只用于演示责任所有权、延迟、发布耦合、故障隔离和恢复门禁，不是任何企业的生产观测。
- 页面最多进入“拆分评估”，不会宣称服务拆分已经完成或产生经营改善。

固定来源和许可见 `source.json`。
