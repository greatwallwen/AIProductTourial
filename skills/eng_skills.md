# Agent/Skill 工程层 Skill 库

每个 Skill 六槽结构化（触发条件/输入/澄清问题/PRD 片段/验收标准/复用范围），发布前经 `skill_lint.mjs` 扫描。8 个 Skill 对应 S01-S08 案例，覆盖分诊→体检→简报→机会图→海报→PPTX→PixiJS→3D 全链路。开源 Skill 只作结构参考，课程保留实际采用的触发条件、输入输出、许可和测试。

共 8 个 Skill（核实 2026-08）。

## capability-router

- 类型：守护型
- 触发条件：当请求进入 Skill 路由前，需先检查输入齐全与动作允许时
- 输入：用户请求 + 可用 Skill 清单 + 权限矩阵
- 澄清问题：输入字段齐全吗？请求的动作在允许列表里吗？缺输入或越权时停止还是降级？
- PRD 片段：先检查输入齐全与动作允许，缺输入或越权时停止并报原因——不猜测缺失字段、不绕过权限（结构参考：openai/skills，课程自有实现，核实 2026-08）
- 验收标准：缺输入时停止并报缺失字段、越权时停止并报原因、不猜测不绕过
- 复用范围：S01 分诊

## data-profile

- 类型：只读型
- 触发条件：当需要对数据源做完整只读扫描、生成体检报告时
- 输入：数据源连接 + 扫描范围
- 澄清问题：扫描哪些表/字段？只读不写吗？报告格式是 JSON+MD 吗？
- PRD 片段：只读完整扫描，生成 JSON+MD 体检报告——字段类型/空值率/唯一值/值域分布，不改数据（结构参考：openai/skills，课程自有实现，核实 2026-08）
- 验收标准：只读不改、JSON+MD 双格式、字段覆盖完整
- 复用范围：S02 数据体检

## metric-brief

- 类型：构建型
- 触发条件：当需要从数据计算指标并生成经营简报时
- 输入：指标定义 + 数据源 + 读者
- 澄清问题：指标可计算吗？哪些字段缺失导致不可计算？简报给谁看？
- PRD 片段：计算指标+经营简报，保留"不可计算"格子——不填默认值、不跳过缺失，不可计算标明原因（问题框定参考：deanpeters/Product-Manager-Skills，课程自有实现，核实 2026-08）
- 验收标准：不可计算指标有"不可计算"格子并标原因、可计算指标有数值和来源、简报结构完整
- 复用范围：S03 会员简报

## product-opportunity-map

- 类型：构建型
- 触发条件：当需要从用户原话提取机会点并画成机会图时
- 输入：用户原话/访谈记录 + 产品上下文
- 澄清问题：原话够吗？每个机会点能追溯到哪句原话？机会点之间有依赖吗？
- PRD 片段：原话→机会图，每节点带 source_refs——不凭空生成机会点，每个节点标注来源原话行号（问题框定参考：deanpeters/Product-Manager-Skills，课程自有实现，核实 2026-08）
- 验收标准：每个机会点有 source_refs、无凭空生成、节点间依赖标明
- 复用范围：S04 机会图

## poster-recipe

- 类型：构建型
- 触发条件：当需要生成多套不同方向、本地可编辑的海报时
- 输入：主题 + 文案 + 视觉方向约束
- 澄清问题：几套方向？每套差异在哪？输出 SVG 可编辑吗？
- PRD 片段：三套不同方向+本地可编辑 SVG——每套有独立配色/排版/信息层级，SVG 可在本地编辑器改文字和颜色（视觉配方参考：LiamGvchi/gc-minimal-zine-poster，课程自有实现，核实 2026-08）
- 验收标准：三套方向有差异、SVG 可编辑、文字和颜色可本地改
- 复用范围：S05 海报

## slide-plan

- 类型：构建型
- 触发条件：当需要从大纲生成可编辑 PPTX 并附逐页备注时
- 输入：大纲 + 读者 + 演示场景
- 澄清问题：每页一个结论吗？备注写什么？模板布局固定还是自由？
- PRD 片段：大纲→可编辑 PPTX+逐页备注+检查——每页一个核心结论，备注写讲述要点和数据来源，生成后做逐页检查（模板布局参考：tristan-mcinnis/pptx-from-layouts-skill，课程自有实现，核实 2026-08）
- 验收标准：PPTX 可编辑、每页一结论、逐页备注完整、检查无空页无溢出
- 复用范围：S06 PPTX

## pixijs-game-contract

- 触发条件：当需要用 PixiJS 做键盘控制+倒计时+重启的原型时
- 输入：游戏规则 + 操作键位 + 资源清单
- 澄清问题：键盘控制响应吗？倒计时准吗？重启会泄漏资源吗？
- PRD 片段：键盘控制+倒计时+重启+资源释放——PixiJS v8，重启时 destroy 旧场景和纹理，不泄漏 GPU 内存（PixiJS v8 参考：pixijs/pixijs-skills，课程自有实现，核实 2026-08）
- 验收标准：键盘控制响应、倒计时准确、重启无资源泄漏、destroy 调用完整
- 复用范围：S07 PixiJS 原型

## asset-contract

- 类型：守护型
- 触发条件：当需要检查 3D 资产格式与性能预算时
- 输入：3D 模型文件 + 性能预算 + 目标平台
- 澄清问题：格式对吗？面数/纹理超预算吗？目标平台跑得动吗？
- PRD 片段：格式/性能预算检查+Three.js 查看器——检查 glTF/GLB 格式合规、面数和纹理尺寸在预算内，附 Three.js 查看器供本地预览（3D 资产参考：DeemosTech/rodin3d-skills，课程自有实现，核实 2026-08）
- 验收标准：格式合规、面数/纹理不超预算、Three.js 查看器可预览
- 复用范围：S08 3D 资产检查
