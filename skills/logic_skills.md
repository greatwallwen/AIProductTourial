# 逻辑底层 Skill 库

每个 Skill 六槽结构化（触发条件/输入/澄清问题/PRD 片段/验收标准/复用范围），由 cangjie-skill-main 把逻辑学方法论 skill 化。15 个逻辑 skill，作为所有案例的方法论锚点。逻辑底层不直接产出工件，而是在每个工程 Skill 执行时做方法论把关。supergrill 方法论内核（superpowers + grill-me 结合）单独见 `supergrill.md`。

共 15 个 Skill（核实 2026-08）。

## proposition-clarification

- 类型：构建型
- 触发条件：当用户提出模糊描述、主观感受或无法验证的陈述时（"感觉""好像""大概""有问题""不对劲"）
- 输入：模糊表述 + 可用数据字段清单
- 澄清问题：这是谁的问题？痛在哪个业务动作上？不解决的代价是什么？
- PRD 片段：把模糊表述转化为可验证命题（陈述句+名词+具体名词），输出结构化交付物并标注数据来源
- 验收标准：命题一句话可证伪、绑定可计算指标、注明数据来源与边界
- 复用范围：01 章逻辑证据

## induction-three-prerequisites

- 类型：验收·守护型
- 触发条件：当用户基于样本数据得出归纳结论时（"数据表明""统计显示""趋势是"）
- 输入：归纳结论 + 样本数据
- 澄清问题：变量间确实有关联吗？对比基准恰当吗？样本充分吗？
- PRD 片段：检验归纳可靠性三前提——相关性（变量间有关联）、参照系（对比基准恰当）、数据量（样本充分），不满足的标明
- 验收标准：三前提逐条有答案、不满足的标明、不跳过
- 复用范围：01 章归纳

## universe-subset-distinction

- 类型：验收·守护型
- 触发条件：当用户比较两组聚合数据时（"整体/全场/总量/平均""达标/正常"）
- 输入：聚合指标 + 子集分布
- 澄清问题：整体达标是否因为子集混在一起？各子集分别达标吗？
- PRD 片段：检查是否犯了"把不同集合的个体混在一起"的错误，避免辛普森悖论
- 验收标准：整体与子集分别核算、子集差异不掩盖
- 复用范围：B16 风机下偏

## reference-frame-selection

- 类型：验收·守护型
- 触发条件：当用户比较两组数据或评估指标是否"高/低/异常"时（"比X高/低""和X比""正常/异常"）
- 输入：比较陈述 + 对比基准
- 澄清问题：对比基准合理可比吗？不同工况/季节/基线能直接比吗？
- PRD 片段：检查参照系是否合理可比，不同工况/季节/基线需归一化
- 验收标准：参照系可比、不可比处标明、归一化方案有据
- 复用范围：B14/B18

## correlation-not-causation

- 类型：验收·守护型
- 触发条件：当用户从"两组数据一起变化/相关"推出因果结论时（"因为X所以Y""X导致了Y"）
- 输入：共变数据 + 因果陈述
- 澄清问题：有混杂变量吗？是实验还是观察？随机分配了吗？
- PRD 片段：阻断相关性→因果性的跳跃，要求保留混杂变量检查
- 验收标准：因果结论标明实验/观察、混杂变量列出、观察性数据不写因果
- 复用范围：B02 发券实验

## falsification-thinking

- 类型：构建型
- 触发条件：当用户提出理论/假设/结论并需评估其科学性时（"这个理论对吗""能证明吗""一定如此吗"）
- 输入：待检验结论 + 验收口径
- 澄清问题：这个结论能否被反例推翻？反例长什么样？找不到反例≠证实
- PRD 片段：检查"能否被反例推翻"而非"能否被正例证实"，设计验收标准先构造反例条件
- 验收标准：有可构造的反例、反例条件写成测试、找不到反例≠证实
- 复用范围：11 章 TDD

## logic-boundary-guard

- 类型：验收·守护型
- 触发条件：当推理涉及安全/伦理/高影响决策，或证据不足以支撑确定结论时（"自动/一定/必须"）
- 输入：推理链 + 影响评估
- 澄清问题：证据够吗？错了代价多大？能自动执行吗？
- PRD 片段：在证据不足或影响重大时悬置判断并交由人工
- 验收标准：高影响动作标人工复核、证据不足不强行下结论、有回退路径
- 复用范围：S01 分诊停止

## quantifier-rigor

- 类型：验收·守护型
- 触发条件：当用户使用全称（所有/全部/每个）或存在（有些/存在/至少）量词时
- 输入：量化陈述 + 数据样本
- 澄清问题：是全称还是存在？从几个样本推的？样本能代表全集吗？
- PRD 片段：检查量词使用是否严谨，避免混淆全称与存在，从个别推全部时标注
- 验收标准：全称/存在标注正确、全称结论有穷举证据、个别样本不推全称
- 复用范围：B17 切刀

## logic-consistency-conditions

- 类型：验收·守护型
- 触发条件：当推理涉及时序数据、不同工况段数据混合、或缺失值填补时（"混合/混算/平均""填补/插值/覆盖"）
- 输入：混合数据 + 条件要素
- 澄清问题：条件要素是否被偷换？不同段的数据能混算吗？填补的依据是什么？
- PRD 片段：检查逻辑一致性的条件要素是否被偷换
- 验收标准：条件要素一致、不同段不混算、填补有依据
- 复用范围：B14 浮选

## induction-exception-warning

- 类型：验收·守护型
- 触发条件：当用户使用归纳结论并可能当作必然结论使用时（"规律是/趋势是/模型表明"）
- 输入：归纳结论 + 使用场景
- 澄清问题：这是统计规律还是必然结论？存在例外吗？能无条件信任吗？
- PRD 片段：提醒归纳结论是或然的，必然存在例外，不能无条件信任
- 验收标准：归纳结论标"或然"、列出已知例外、不当作必然使用
- 复用范围：B15 半导体

## identity-law-check

- 类型：验收·守护型
- 触发条件：当推理涉及多个概念/变量/传感器/工序，且可能存在概念指代漂移时（"X和Y混在一起""不分组直接算""混用/混淆"）
- 输入：多概念陈述 + 分组需求
- 澄清问题：每个概念含义一致吗？有没有偷换概念？该分组的分了吗？
- PRD 片段：检查每个概念的含义是否保持一致，防止偷换概念
- 验收标准：概念定义一致、该分组的已分组、无偷换
- 复用范围：13 章六槽

## exclusivity-possibility-analysis

- 类型：验收·守护型
- 触发条件：当用户得出结论并需判断其强度时（"一定/必然/可能/也许/只能/排除了其他"）
- 输入：结论 + 强度措辞
- 澄清问题：这是必然、可能还是排他？排除了其他可能性吗？
- PRD 片段：分类结论强度，检查是否排除了其他可能性
- 验收标准：结论强度标注正确、排他结论有排除证据、可能结论不写必然
- 复用范围：B19 液压

## logic-three-step

- 类型：构建型
- 触发条件：当用户面对复杂问题需要开始逻辑分析时（"怎么分析/从哪开始/怎么推理"）
- 输入：复杂问题
- 澄清问题：命题是什么？命题间逻辑关系是什么？链条怎么连？
- PRD 片段：提供"命题化→逻辑关系→逻辑链条"三步框架，确保分析从明确命题开始
- 验收标准：从命题开始、关系明确、链条完整
- 复用范围：01 章推理

## fact-opinion-separation

- 类型：验收·守护型
- 触发条件：当用户陈述混合可验证事实与主观价值判断时（"我觉得/我认为/应该/好坏/对错"）
- 输入：混合陈述
- 澄清问题：哪句是可验证事实？哪句是主观观点？事实能查证吗？
- PRD 片段：区分事实（可验证真假）与观点（主观判断），确保推理建立在事实上
- 验收标准：事实与观点分离标注、事实可查证、观点不冒充事实
- 复用范围：S03 简报

## spdc-method

- 类型：构建型
- 触发条件：当用户需要系统分析数据/解决问题并需结构化流程时（"怎么分析数据/从哪开始/数据流程"）
- 输入：待分析问题 + 可用数据
- 澄清问题：问题是什么（State）？计划是什么（Plan）？怎么执行（Do）？结论是什么（Conclude）？
- PRD 片段：提供 State/Plan/Do/Conclude 四步框架
- 验收标准：四步齐全、每步有产出、结论可追溯到数据
- 复用范围：数据分析
