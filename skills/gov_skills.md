# 交付治理层 Skill 库

每个 Skill 六槽结构化（触发条件/输入/澄清问题/PRD 片段/验收标准/复用范围），发布前经 `skill_lint.mjs` 扫描。3 个 Skill 守护"能不能发"的最后一道关卡：TDD 守代码层、multi-agent-review 守评审层、skill_lint 守 Skill 发布层。三层之间不是堆叠，而是逻辑闭环——TDD 是证伪第一道，multi-agent-review 是独立审查，skill_lint 是发布前门禁。

共 3 个 Skill（核实 2026-08）。

## test-driven-development

- 类型：守护型
- 触发条件：当需要为功能写测试并按红绿重构协议推进时
- 输入：功能需求 + 验收口径
- 澄清问题：反例长什么样？先写红测试了吗？绿测试消除反例了吗？
- PRD 片段：红绿重构协议——先写红测试（构造反例条件），再写绿测试消除反例，任一步跳过即视为未完成；TDD 只保证"已知反例被消除"，不保证"没有未知缺陷"（来源：jnMetaCode/superpowers-zh，7.5k star 套件，单卡，核实 2026-08）
- 验收标准：红测试先写、绿测试消除反例、无跳步、已知反例清单完整
- 复用范围：B05 转运单校验

## multi-agent-review

- 类型：守护型
- 触发条件：当代码/工件需要多视角独立审查时
- 输入：待审工件 + 审查维度
- 澄清问题：审查的人独立于做的人吗？几个视角并行？问题清单如何变成门禁？
- PRD 片段：Review Board 模式——3 agent 并行审（工程/判断/验证三视角），Tech Lead 汇总；工程视角查指标可计算与硬编码，判断视角查因果成立与异常有责任人，验证视角查可自动核对断言；Maker/Checker 分离，验的人独立于做的人（来源：harish-info/claude-code-skills，核实 2026-08）
- 验收标准：3 agent 并行独立、三视角各有输出、Tech Lead 汇总问题清单、问题可写成可自动检测守卫
- 复用范围：B16 风机评审

## skill_lint

- 类型：守护型
- 触发条件：当 Skill 发布前需做路由/样本/安全/版本四类检查时
- 输入：Skill 定义文件
- 澄清问题：路由完整吗？样本可复算吗？有安全注入风险吗？版本一致吗？
- PRD 片段：Skill 发布前四类检查——路由完整性（触发条件→输入→输出闭环）、样本可复算（验收标准有可执行样本）、安全注入（无未转义输入/无越权）、版本一致性（来源标注与实际一致）（来源：skill-scanner，13 章引用，核实 2026-08）
- 验收标准：路由无断链、样本可复算、无安全注入、版本标注一致
- 复用范围：13 章治理
