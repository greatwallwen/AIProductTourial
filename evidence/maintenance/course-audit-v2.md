# Course_AIProduct 重构审计（2026-07-30）

## 结论

这次不在旧教程上继续加章节，也不再把“有代码、有截图”当成案例完成。发布工作树已经具备可复用的课程骨架、20 组本地化数据和20个行业工作台，但三处结构性问题尚未解决：

1. 编号、目录和路由存在两套口径。课程使用 `B01`，运行时仍使用 `01`，Prompt 又同时出现 `U01` 与 `P01`。在 228 个文件中检出 1,867 处两位旧编号，公开链接同时存在 `/cases/18/work`、`/cases/B18/work` 等形式。
2. 案例的业务画面被通用外壳稀释。20 个案例已经有各自的工作台组件，不是同一页面简单换标题；但“问题、数据、记录、恢复”等通用页面仍占据主导航，技术路径、哈希和内部状态进入了用户界面。结果是产品看起来像案例说明器，而不是岗位人员可以操作的行业软件。
3. 教程内容多但路线不够稳。主 Markdown 已覆盖 Prompt、Agent + Skills、Loop、架构和20个案例，正文约 32 万字节；但章节从“第四部分”直接跳到“第六部分”，Prompt 的 `U` 编号与清单的 `P` 编号不一致，案例写法高度重复，案例之间的难度进阶没有形成清晰台阶。

因此，后续采用一条主线：先统一合同，再做一个达到参考原型精度的金样案例，随后按行业逐案重构，最后重写教程。PPTX 不进入当前关键路径。

## 课程结构审计

### 可保留的部分

- 课程主标题“AI 时代产品工程：从业务问题到可验证智能系统”准确，不改。
- “Prompt → Agent + Skills → Loop → 产品与架构 → 综合案例”的能力路线成立。
- Prompt 已有 18 个实验入口，Agent + Skills 已有 8 组能力单元，Loop 已有 4 种模式，内容不是空白重做。
- 20 个综合案例覆盖零售、运营、医疗、城市治理、工业、能源等场景，现有数据足以支持第一轮重构。
- 讲师教程中已经清掉大部分生硬术语：`SHA-256`、`证据边界`、`失败分支`、`讲师使用说明`、`讲师工作坊`、`Request ID` 当前均为 0 次。这里不能倒退。

### 必须修正的部分

| 问题 | 当前表现 | 新合同 |
|---|---|---|
| 编号冲突 | `U01/P01`、`B01/01` 并存 | 只使用 `P001…`、`S001…`、`L001…`、`B001…`；排序另用 `display_order` |
| 章节断层 | 第四部分之后直接出现第六部分 | 合并为五层：基础判断、Prompt、Agent + Skills、Loop 与架构、综合案例 |

| 技术回执挤入正文 | 页面和部分材料展示路径、内部状态和校验信息 | 回执留在 `evidence/`；正文只保留讲课需要的界面结果、命令和故障处理 |

### 新知识底座

1. **基础判断**：大模型会生成什么、哪里会错、产品如何把结论变成可复查的决定。
2. **Prompt**：从写清任务到约束输入、输出、反例和检查方法；以多种短实验建立直觉。
3. **Agent + Skills**：把单次回答扩成可调用数据、文件、浏览器和生成工具的完整任务，同时把 Agent 与 Skills 合并讲解，避免重复。
4. **Loop 与系统架构**：状态、停止条件、人工接管、重试、持久化和多角色协作；再进入 DDD、事件、RAG、MCP/A2A 与长期任务。
5. **综合案例**：24 个行业产品，每案都有数据、主要岗位、可运行流程、异常路径、持久结果和真实截图。

课程不按固定天数组织；两天、四天或专题班只是从同一知识底座中选取不同路径。

## UI 与运行时共同合同

### 每个案例必须具备

1. 一个明确岗位和一个当下必须做出的业务决定。
2. 一个主画面，而不是“概览页之后才进入真正工作”。默认路由直接进入主要工作台。
3. 至少三种业务状态：初始、异常/信息不足、完成人工动作后的结果。
4. 至少一条错误路径，能在界面内恢复，不用刷新重来。
5. 一次会改变状态的人工操作，刷新页面后仍能看到结果。
6. 一份可以带走或继续流转的结果，如核验单、工单、路线、会签、补货任务或复测请求。
7. 真实浏览器截图；Image2 设计稿只作为视觉参照，不能冒充运行证据。

### 视觉规则

- 每案先用 Image2 生成三张 1440×900 设计候选，再从信息架构、行业真实感、主任务清晰度、可实现性四项选择一张。
- 选中的设计图是主视口和关键状态的字面参照，不只是配色灵感；布局、层级、密度和动效都要对齐。
- 暗色工业台只用于工业、设备、能源等需要现场态势的案例；零售、研究、医疗、信审等按岗位习惯使用亮色或混合主题。
- Three.js 只用于空间位置、设备结构、因果路径或视角操作确实能帮助判断的案例，优先 B016、B018、B019；不能用作无意义背景。
- 动画必须表达状态变化、数据流、证据路径、时间进展或人员接力。纯装饰轨道、漂浮粒子和与案例无关的首页场景全部删除。
- 界面不出现“讲师提示、案例目标、证据边界、SHA、文件路径、fixture、已验证”等内部文字。
- 桌面端固定验收 1440×900；本轮不做移动端。

### 金样选择
